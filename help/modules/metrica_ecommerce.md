# Метрика: электронная коммерция

Модуль связывает действия покупателя с Яндекс Метрикой. Он не меняет цены,
корзину, заказ и оформление страниц. Нужны установленные и включённые модули
«Товары» и «Магазин»; для изменений корзины нужен «Магазин» версии 1.8.10 или новее.

## Подключение

1. Откройте **Модули → Метрика: электронная коммерция → Настройки**.
2. Введите числовой номер счётчика из Яндекс Метрики. Пароль не нужен.
3. Если счётчик уже подключён общим шаблоном, системным блоком или менеджером
   тегов, оставьте **Уже установлен на сайте**. Модуль не будет вставлять его
   второй раз. В настройках существующего счётчика включите электронную
   коммерцию, контейнер должен совпадать с настройкой модуля (`dataLayer`).
4. Если счётчика нет, выберите **Подключать модулем**. В этом режиме модуль
   загружает код Яндекса и инициализирует ecommerce. Вебвизор необязателен.
5. Выберите события, включите интеграцию и пока оставьте тестовый режим.
6. Сохраните. В соседней вкладке откройте сайт, товар, добавьте его в корзину,
   измените количество, удалите. Вернитесь во вкладку **Проверка**.
7. После проверки выключите тестовый режим. Для проверки реального приёма
   используйте инструменты самой Метрики, а не только журнал модуля.

Нельзя одновременно оставлять старый собственный скрипт отправки ecommerce
и включать такие же события модуля: получится двойной учёт. Обычный счётчик
оставить можно. Модуль автоматически не удаляет код из ваших шаблонов.

## Что учитывается

- Показы карточек: когда не меньше половины карточки видно на экране.
- Переход из карточки: ссылка на основной товар, не переключение миниатюры.
- Просмотр товара: фактическая страница товара, включая повторное открытие.
- Добавление/удаление: только изменение количества после успешной операции.
  Увеличили с одного до трёх — добавлено два. Ошибка и откат не считаются.
- Покупка: заказ действительно создан публичным оформлением. Берутся ID
  товаров, состав, цены с акциями и итог товаров со скидками, без доставки.
  Подарки имеют нулевую цену. Общая купонная скидка учтена в доходе заказа.
- Начало оформления: JS-цель `ave_begin_checkout`.
- Оплата подтверждена: JS-цель `ave_payment_confirmed`, не повторная покупка.

Обе JS-цели создайте в интерфейсе Метрики. ID товара остаётся ID документа,
а ID покупки — номер заказа. Это не идентификаторы покупателя.

Очень большой заказ делится на части, чтобы уложиться в ограничение Яндекса
8192 символа на объект. Части имеют номера вида `123-1`, `123-2`; доход
распределяется между ними, не дублируется. Число покупок в отчёте в этом случае
соответствует числу частей, а не числу исходных заказов.

## Проверка и ограничения

В тестовом режиме модуль ничего не помещает в рабочий dataLayer и не вызывает
цели Яндекса. Уже установленный отдельно счётчик при этом продолжает работать.
Журнал хранит последние 50 событий только в браузере; он не является журналом
доставки. «Передано в JS» означает постановку в очередь JavaScript, не ответ Яндекса.

Повторная загрузка страницы и повторное чтение очереди не должны повторять
покупку: используются ID события, подтверждение очереди с CSRF и память
браузера. При недоступности хранилища браузера защита слабее; абсолютную
доставку ровно один раз браузерная аналитика не гарантирует.

Если после заказа покупатель ушёл в банк, событие будет передано при возвращении
на сайт или следующем открытии страницы в той же сессии. Очередь живёт сутки.
Проверка оплаты отслеживает только заказы этой сессии, не старые заказы из БД;
наблюдение действует до семи дней. Без возвращения посетителя оплата не попадёт
в цель. Для гарантированного серверного учёта нужен отдельный механизм импорта
конверсий. Ручные и импортированные заказы не считаются посещениями сайта.

На новом шаблоне карточки используйте штатный `data-product-card`, внутри
`data-item` с ID товара и микроданные `itemprop="name"`, `itemprop="price"`
с числовым `content`. Дополнительно поддерживается обычный `.product-card`.
Необязательный `data-metrica-list` задаёт название списка. AJAX-карточки
подхватываются автоматически. Событие `commerce:cart-updated` обновляет очередь;
стандартная замена мини-корзины тоже поддерживается.

Модуль не передаёт имена, телефоны, email, адреса, токены заказа и платёжные
ключи. Настройку согласия на аналитику и политику сайта необходимо учитывать
отдельно. Выключение пакета прекращает его подключение; самостоятельно
встроенный счётчик останется в шаблоне.

Формат событий: [документация Яндекса](https://yandex.ru/support/metrica/ru/ecommerce/data).
